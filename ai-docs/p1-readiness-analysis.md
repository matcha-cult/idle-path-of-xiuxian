# 放置·修仙之路 — P1 实现就绪度分析

> 本文档分析 P1（物品与词缀系统）在进入实现阶段前需要解决的所有决策项。
> 设计文档：`ai-docs/poe-xiuxian-restyle-design.md`
> P1 落地清单：设计文档 §7.1（9 步）

---

## 1. P1 范围回顾

P1 目标：**将 PoE 的物品/词缀系统以修仙风格落地为可运行的代码**

产出物：
- 独立 game 数据库（6 张表）
- 物品基底库（item_bases）+ 铭文池（affixes）seed 数据
- 物品实例生成器（roll 铭文）
- 背包/装备/卸下/丢弃 REST API
- typecheck + build 验证通过

---

## 2. 阻塞性决策（必须拍板才能开始编码）

### 决策 2-1：数据库形态

| 选项 | 描述 | 影响 |
| --- | --- | --- |
| A（推荐） | 独立 game 库 `GAME_SERVICE_DATABASE_URL` + 独立 Prisma schema | 与用户系统完全隔离；需新增连接配置、独立 migration |
| B | 复用现有用户库，game 表加前缀 `game_` | 单库管理简单；但 game 表与用户表耦合 |

**P1 阻塞点**：Prisma schema 文件位置、环境变量命名、DatabaseService 是否新建——全都取决于此决策。

### 决策 2-2：铭文存储方式

| 选项 | 描述 | 影响 |
| --- | --- | --- |
| A（推荐） | `game_items.affixes` JSON 字段 | 简单：一物品一行，直接返回 JSON；按词缀检索需 JSON 查询 |
| B | `game_item_affixes` 独立关联表 | 强：可按词缀高效检索（如「查找所有带锋锐铭文的装备」） |

**P1 阻塞点**：Schema DDL（步骤 1）、物品生成器（步骤 5）、背包查询（步骤 6）的表结构均依赖此决策。

## 3. 非阻塞性决策（可先编码再调整）

### 决策 3-1：模块目录与 API 前缀

| 选项 | 描述 |
| --- | --- |
| A（推荐） | `modules/game/` + `/api/game/*` |

**说明**：此决策不阻塞数据层（步骤 1–3），但影响 Controller 注册（步骤 7–8）。建议 P1 启动时一并确认。

### 决策 3-2：拾取规则默认行为

| 选项 | 描述 |
| --- | --- |
| A（推荐） | P1 默认「丢弃」，P3 后改「分解」 |

**说明**：P1 不涉及分解/出售逻辑（属 P3 通货阶段），默认丢弃是最简实现。此决策不影响 P1 核心。

### 决策 3-3：剧情 5 章框架

**说明**：属 P5 阶段，不阻塞 P1。但物品灵阶的取值范围（1–9）和掉落表设计会受章节结构影响（高灵阶物品仅在后期章节掉落）。P1 的 seed 数据可按灵阶 1–9 全覆盖设计，后续按章节限制即可。

### 决策 3-4：混沌争夺战框架

**说明**：属 P6 阶段，不阻塞 P1。

### 决策 3-5：实施阶段排序

| 选项 | 描述 |
| --- | --- |
| A（推荐） | P1 物品 → P2 功法 → P3 通货 → P4 放置 → P5 剧情 → P6 混沌 |

**说明**：排序已体现在设计文档中。P1 作为基石阶段，后续阶段均依赖其物品体系。

## 4. 需在 P1 编码前明确的技术细节

以下细节虽不构成「阻塞」，但在编码开始前明确可避免返工：

### 4.1 铭文效果字段

文档 §4.9 定义了 12 个效果字段。需确认：
- `lingyun_gain` 是否在 P1 直接使用（Set 15 待确认，如未确认则先用 `exp_gain` 占位）
- 是否需要为 13 种通货预留铭文效果（如「物品掉落稀有度」）
- `spirit_power_pct` 的 % 如何存储（整数 8 还是字符串 "8%"）

### 4.2 物品基底 seed 数据范围

P1 至少需要的基底数量（建议）：
- 武器（单手）：4–6 种（剑/刀/尺/拂尘/扇/葫芦）
- 武器（双手）：4–6 种（长枪/重剑/长棍/巨斧/幡/鼎）
- 防具 ×5 槽位：每种 2–3 种
- 首饰 ×4 槽位（含双戒指）：每种 2–3 种
- 合计：约 30–50 条 seed 记录

### 4.3 铭文池 seed 数据范围

按文档 §4.3 的铭文类型 × 阶数 × 适用标签的矩阵：
- 阳铭类型：锋锐(atk)、蕴灵(spirit_power)、御土(def)、灼炎(fire)、凝冰(ice)、厚土(earth)、etc.
- 阴铭类型：迅疾(atk_speed)、回春(hp_regen)、悟性(lingyun_gain)、凝神(focus)、etc.
- 阶数：1–4 阶（P1 仅需低阶）
- 适用标签：weapon / body / helmet / gloves / boots / shield / ring / amulet / belt
- 预估：50–100 条 seed 记录

### 4.4 CharacterService 访问修饰符

文档 §7.1 注明：
> `CharacterService.findByUserId` 需由 private 改为 public 供物品服务跨库解析角色归属。

此改动应在 P1 开始时完成，避免物品服务编写时受阻。

## 6. 建议的 P1 启动顺序

假设决策 2-1（独立 game 库）和 2-2（JSON 存储）已获批：

1. **确认环境变量**：`GAME_SERVICE_DATABASE_URL` 的连接串
2. **创建 Prisma schema**：`packages/server/prisma/game.schema.prisma`（6 张表）
3. **编写 init 脚本**：`packages/server/scripts/init-game-db.mjs`（DDL + seed）
4. **实现 GameDatabaseService**：独立 PrismaClient 连接
5. **改造 CharacterService**：`findByUserId` → public
6. **实现铭文服务**：`item.affix.service.ts`（铭文池查询 + 权重 roll + 文本渲染）
7. **实现物品服务**：`item.service.ts`（CRUD）
8. **实现 Controller**：`item.controller.ts`（10 个接口）
9. **模块接入 + 验证**
