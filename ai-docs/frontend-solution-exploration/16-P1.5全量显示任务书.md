## 1. ⚠️ 一处必须澄清的规则冲突（**已在本文拍板，请按此实现**）

用户原话是「让**未解锁传送点**的节点不可交互」。**照字面实现会死锁**：

> 传送点是**到达该节点之后**才点亮的（`settings-revision-2.md` §5.2；`map.service.ts` 的 `enter`
> 里 `waypointOpen = existing?.waypoint_unlocked || node.has_waypoint`）。
> 若把「传送点已点亮」当成**进入**该节点的闸门，则**第一个节点就进不去**（它自己传送点未亮）
> ⇒ 一步都走不了。

**因此本文拍板如下（三层互不冲突）**：

| 闸门 | 判据 | 效果 |
| --- | --- | --- |
| **可见** | **无**（全部下发） | 所有节点都画在画布上 |
| **可交互 / 可前往（走路）** | **`discovered === true`**（前置已到达，或自己是入口） | 画布上可选中；右栏有「前往此地」 |
| **可传送（直达）** | `node.progress.waypointUnlocked === true` | 右栏有「传送至此」；传送点图标**实心** |

于是：
- `discovered === false` → **不可交互**（用户要的那条，挂在「是否已探明」上）；
- 已探明但传送点未点亮 → **能走过去、不能传送**（传送点图标**空心**）。

> 这样「未解锁传送点的节点」在**传送**这个语义上确实不可交互，同时不破坏跑图。
> **如果用户要的是别的口径，改 §1 这一张表即可，不要改其余部分。**

## 3. T1 · 协议（`packages/ionet-transport/src/api/dto.ts`）

export interface MapNodeView {
  // ...现有字段不动...
  /** 是否已探明（前置已到达，或自己是入口）。false 时 name/level/threshold/description/featureKey/zoneCode 均为 null */

## 5. T3 · 未探明节点的脱敏（**别漏，漏了就是剧透**）

`discovered === false` 时，以下字段一律下发 **`null`**：
`name` / `level` / `threshold` / `description` / `featureKey` / `zoneCode`。

仍保留：`id` / `code` / `gridRow` / `gridCol` / `kind` / `ring` / `sector` / `chapter` /
`hasWaypoint` / `orderIndex` / `progress` / `discovered`。

> 理由：`code` 是 key（前端要它做 React key 与选中标识），坐标是画点必需；
> **但名字与数值是玩法信息，不给才不剧透** —— 玩家知道「那边有东西、还没去过」就够了。
> `kind` 保留是为了让秘境峰仍显示 ⚔ 轮廓（否则连「那边是秘境」都看不出，探索欲反而更低）。

## 6. T4 · 前端四态落地

`canvas-view.ts` 的 `nodeVisualState()` 现在必须**真的返回 `unknown`**：

| 态 | 判据 | 视觉 |
| --- | --- | --- |
| `current` | `code === currentCode` | 金圈 + glow + 尺寸最大 |
| `visited` | `progress.visited` | 亮蓝实心 |
| `known` | `discovered && !visited` | 暗蓝实线 |
| `unknown` | `!discovered` | **虚线淡灰轮廓、无文字、不可交互** |

**交互闸门**（对应 §1 那张表）：

- `discovered === false` → 传给 `GraphCanvas` 的 item 设 **`disabled: true`**：
  **不可选中、无 hover 高亮、不触发 `onSelect`**（`GraphCanvas` 已支持 `disabled` 语义，复用即可）；
- **传送点 glyph**：`hasWaypoint && !progress.waypointUnlocked` → **空心**；
  `waypointUnlocked` → 实心。未探明节点的传送点**不画 glyph**（连有没有传送点都不剧透）。

## 7. T5 · 右栏与图例

- 选中一个**已探明**节点：与现在一致（详情 + 战力对比 + 「前往此地」）；若传送点已点亮，**再加**「传送至此」。
- 选中一个**未探明**节点：**因为 `disabled` 它根本选不中**，所以右栏只会显示「当前/上次选中」的节点。
  右栏**不得**出现「前往此地」按钮（`discovered === false` 时该按钮不渲染）。
- 图例（`MapCanvasLegend`）：四态文案补齐 —— **「未探明」这一态现在真的会出现**，
  检查它的措辞不要让玩家以为「点不动 = 坏了」。
- 底部提示条（`MapHintBar`）：补一句「虚线灰点为未探明区域」。
