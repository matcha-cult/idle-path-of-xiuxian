## 1. ⚠️ 先修荒诞点：怪物数据只属于「有战斗的枢纽」

**问题**：17 个节点**全都**带 `level` / `threshold` —— 北门 `level=2/threshold=25`、
传法院 `level=3/threshold=55`、青云主峰 `level=5/threshold=100`。
于是宗门内的**藏经阁、山门**都会显示「怪物境界 第 N 境」，正如用户所说：**宗门内总不能天天杀同门**。

**修法（数据分层）**：

1. `game_map_nodes.level` / `threshold` 改为 **nullable**；
   **只有 `kind='secret_realm'` 的节点填值**（本轮 = 第八峰·历练；以后「山下凡尘」的战斗节点同理）。
2. 其余 16 个节点 `level` / `threshold` 置 **null**。
3. **右栏详情按 `level === null` 分流**：
   - `level != null`（有战斗）→ 显示「怪物境界 / 参考战力」；
   - `level == null`（功能型枢纽）→ **完全不显示战斗数据**，改为显示该地的**职能对象**
     （已有的 11 个 `game_map_objects`）。
4. D10 的表述随之修正：**「青云宗·历练峰历练到第五境」**（不是全图每个点都是怪）。
5. 自检加一条：**`kind != 'secret_realm'` 的节点不得带 level/threshold**。

> 顺带：这条修完，用户截图里那句「怪物境界 第 4 境 难度参考门槛 65」就不会再出现在宗门地点上了。

## 2. 「在线」的定义（R2 §4.2，别自己发明）

> **在线 = 存在一条活着的 WS 会话（应用层心跳 `system.ping` 未判死）** + **页面可见**。
>
> - 会话断开或判死 → 立即不算在线，**服务端不再推进**；
> - `visibilitychange → hidden` 不算在线（否则挂一夜标签页 = 离线也能刷进度）；
> - **禁止**由客户端上报在线时长（可伪造）。这是本设计唯一需要借力的既有机制。

## 3. 在线探索 tick（R2 §4.2 六步，服务端权威）

| 步 | 内容 |
| --- | --- |
| 1 | 每 tick 按「战力碾压比」结算本轮击杀数 |
| 2 | 按掉落表判定产出（灵韵/物品），走既有辨宝抽取 |
| 3 | 累计本层击杀 → 达标则 `floor + 1` |
| 4 | `floor` 命中 `boss_every_floors` → **Boss 层**：Boss 未被击败前不涨层 |
| 5 | 击败**第一个** Boss → 置 `game_node_progress.idle_unlocked` + **推送解锁提示**（D2） |
| 6 | 战力不足 → **卡层**：不涨层，**原地刷当前层**（仍有产出、无进度），UI 给「战力不足，还差 N」 |

**明确不做**（R2 §4.2 原文）：
- ❌ 客户端**不本地涨层、不本地算产出**（否则与服务端权威冲突）；
- ❌ **不做任何形式的「离线补算探索进度」**，包括登录时按离线时长一次性推进。

### 3.1 数值：**全部放进一处可调常量**（我的提议，用户可改）

本轮必须定几个新数字。**请集中放在一个显眼的配置对象里并加注释**，方便以后一键调：

```ts
/** 在线探索节奏（可调） */
export const ONLINE_TICK = {
  tickMs: 1000,              // 结算节拍
  pushEveryMs: 3000,         // 推送节流（别每 tick 都推）
  killsPerSecondBase: 1,     // r=1 时每秒击杀
  ratioClamp: [0.5, 4],      // 碾压比的夹取区间
  killsPerFloor: 30,         // 普通层涨层所需击杀
  idleKillsPerSecCeiling: 20,// 单 tick 击杀上限（防爆）
} as const;
```

- **击杀速率** = `clamp(r, 0.5, 4) × killsPerSecondBase` 只/秒，其中 `r = playerPower / 本层门槛`；
  ⇒ r=1 时 1 只/秒，r=3 时 3 只/秒，r=0.5 时 2 秒 1 只；
- **卡层判定**沿用既有公式 `playerPower < basePower + (floor-1)×powerStep`（zone.service 已有），
  **不要另写一套**；
- **涨层所需击杀** = `killsPerFloor`（30），Boss 层单独处理（打不赢 Boss 就停在 Boss 层原地刷）。

## 7. 测试要求（边界必须覆盖，`AGENTS.local.md` §4 是硬约束）

**服务端**：
- **离线不推进**：无在线会话时，跑 N 个 tick，`floor` 与击杀数**一动不动**；
- **在线才推进**：登记在线后跑 N 个 tick，击杀数/层数按公式增长；
- **卡层**：`playerPower` 低于本层门槛 → `floor` 不变、**但产出仍在累计**、且给出「还差 N」；
- **Boss 层**：`floor = 3` 时涨层暂停；击败 Boss → `idle_unlocked = true` + 推送一次（**不重复推送**）；
- **解锁幂等**：重复击败不重复置位、不重复推送；
- **节流**：1 秒 tick 下 10 秒内推送次数 ≤ `ceil(10000/pushEveryMs)`；
- **边界**：`playerPower = 0` / 门槛 = 0 / `r` 极大（触发上限）/ `r` 极小（触发下限）/
  `maxFloor = 1`（无普通层）/ 角色不存在 / 会话断开中途；
- **并发**：同一角色在多个会话同时在线 → 只推进一次（不能翻倍）。

**前端**：
- 右栏分流：`level === null` 的枢纽**不渲染**任何「怪物境界/门槛」文案（防回归）；
- 历练峰面板：进度/层数/卡层提示/解锁引导的渲染与边界（`maxFloor=1`、进度为 0、已解锁）。
