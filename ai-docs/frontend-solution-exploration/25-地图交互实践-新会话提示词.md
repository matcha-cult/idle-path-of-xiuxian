### 4. 与你的任务直接相关的三个缺口

**A. 手感 / 技术路线（用户最在意的那个）**
现状是 `div + CSS` 变换：拖动平移 + `Ctrl+滚轮`缩放 + `zoom_fit` 适配短边（`CANVAS_HEIGHT = 520`）。
用户判定"很难实现我想要的放大缩小拖拽"。可选路线见 §0 的三条。
**建议做法**：先做**最小可交互原型**（同一份数据、同一套 props，路线 ①/②/③ 各来一个薄实现），
让用户在浏览器里真的拖、真的缩放、真的点，**用体感定路线**，然后再正式落地 + 补测试 + 清旧实现。

**B. 「必须和传送点交互之后才可解锁传送」现在没实现** ⚠️ 这是**玩法层面的真实缺口**
- 用户原话要求"**必须和传送点交互之后才可解锁传送**"；
- 现状：`map.service.ts` 在**首次到达**时就自动点亮 `waypoint_unlocked`；
- 前端判定（`canvas-view.ts:79`）：`isNodeInteractive = node.adjacent || node.progress.waypointUnlocked`，
  即"不相邻但传送点已点亮 → 可传送"；
- 要改成"交互后才点亮"，需要 **`map.interact` + 对象进度表** ——
  `24-...md` §2 **B1** 就是这个；`22-...md` §13.3 已确认**石台不需要它**
  （石台是前端就地组件 + 既有 `zone.breakthrough`），但**NPC / 传送点需要**。
- 属**跨端改动**（server 新增 Action + 表 + 单测；transport DTO；web 交互入口 + 状态回读），
  是本轮**最有玩法价值**的一块，但请**先跟用户确认口径**再动：
  交互是"点一下传送点就永久点亮"？还是"消耗道具/看境界"？已有 `game_map_objects` 的 `feature_key`
  体系可复用（主峰 护法堂 = `waypoint`）。

**C. `map.service` 的 `discovered` 过滤器隐患（一行 + 一条测试，建议顺手修）**
`map.service.ts` 约 233-239 行仍按 `discovered` 过滤节点。今天**恰好空转**
（17 个节点的 `requires_node_code` 全是 `null`）。但 `requires_node_code` 正是为剧情前置保留的 ——
**一旦有人填上，那个节点会从大地图悄悄消失**，与"直接显示所有点"的设计冲突。
修法：全量下发，`discovered` 只作**显示标记** + 补一条边界测试。

### 5. 不能破坏的既有契约（除非用户明确说改）

1. **点击枢纽只选中，绝不移动**（反直觉，见 `GraphCanvas` 文件头 + `14` §12.1）；
   移动只走右栏「前往此地」按钮（PC 双击是快捷键）；底部 `MapHintBar` 常驻教这条规则，**别删**；
2. **拖动抑制两层都要留**：容器 `userSelect: 'none'`（含 `WebkitUserSelect`）+
   `onPointerDown` 里 `preventDefault()`；枢纽 `draggable={false}`；SVG 层也 `userSelect: none`。
   —— 用户实测过"拖动飘到左边 / 选中文本 / Edge 选词搜索"，**删任何一条都会回归**（`19` §2）；
3. **枢纽恒定屏幕尺寸**（图标不随 zoom 缩），否则缩到 fit 视图只剩 20px 点不中（`14` §14.3）；
4. **移动期间面板不卸载**：`loading`（骨架屏）只用于首屏 / 整图重载，反馈落在按钮上（踩过"点前往白屏"）；
5. 面板**挂载时不拉取**（首屏由 `RootStore.loadPanel()` 并发加载），三态交给 `AsyncBoundary`；
6. 坐标缺失 / 坐标空间非法 → **自动降级到列表视图**，不崩；
7. 秘境石台（第八峰·后山）与挂机链路**已交付并验收**，别改（`23` §0.1 标了临时方案的边界）。
