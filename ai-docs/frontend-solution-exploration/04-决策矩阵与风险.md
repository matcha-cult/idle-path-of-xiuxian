## 2. 风险清单与缓解

| # | 风险 | 等级 | 缓解 |
|---|---|---|---|
| R1 | 后端生产形态未定：`extension-nestjs` 默认在 `NODE_ENV=production` 拒绝启动 | 高 | 已提供显式开关 `allowProduction`（本项目读 `IONET_ALLOW_PRODUCTION`）；前端契约以「JSON 信封 + 文本帧」为准，Codec 可插拔（06 §5 Q7） |
| R2 | ~~响应无关联字段，并发请求无法配对~~ | ~~高~~ → **已消除** | 【已更新】`reqId` + `kind` 已落地，默认并发；串行仅为兜底 |
| R3 | ~~codegen 产物与线协议不一致（Response 含 cmd/subCmd）~~ | ~~中~~ → **已消除** | 【已更新】生成器已与 `PROTOCOL.md §11` 对齐（不再生成 `cmd/subCmd`） |
| R4 | jprotobuf 二进制格式为移植版私有设计，跨端实现有对齐成本 | 中 | v1 只用 JSON；`PROTOCOL.md §13` 已提供机器可读 schema 清单；A3 codec 已做未知字段透传 |
| R5 | 浏览器 WS 不支持自定义 header → 鉴权形态受限 | 中 | 【已更新】已定：握手 `?token=`（浏览器）/ `Bearer`（Node/小程序）；Q1 关闭。生产建议改用短期握手 ticket 以免 token 进日志 |
| R6 | 移动浏览器后台冻结/掐断 WS | 中 | visibilitychange/onLine 主动断开 + 前台退避重连 + 断线 UI（02 §3.3） |
| R7 | 服务器静默期与"心跳超时判死"的边界 | 低 | 用 `system.ping` 的响应做唯一可预期信号，与业务静默解耦（02 §3.3） |
| R8 | 装饰器配置漂移（工具链升级踩坑） | 低 | 基座 tsconfig + 三连闸 CI + 装饰器冒烟用例；或直接选方案 C 消除该类风险（03 §5） |
| **R9** | **业务错误被漏判**：只看 `errorCode` 会漏掉 `data.success === false` | **高** | 【新增】前端两级判定（传输层 + 业务层），ToastStore 建立业务码映射（06 §2） |
| **R10** | **`kind` 值写错**：早期文档设想的 `'push'` 实际为 `'notification'` | 中 | 【新增】统一用 A3 `isNotificationFrame` / `classifyFrame`，不手写字面量（06 §1 S8） |

## 3. 开放问题（★ 已按 2026-09-13 现状更新）

> **定性**：协议加固已完成，原"求后端拍板"的 Q1~Q4、Q8 已关闭；剩余为业务约定与部署决策。
> 完整现状见 [06 §5](./06-现状校正与实施基线（2026-09-13）.md)。

| # | 问题 | 状态 | 说明 / 拍板后的动作 |
|---|---|---|---|
| Q1 | WS 鉴权形态 | ✅ **已关闭** | 握手 `authenticate`；浏览器 `?token=`，Node `Bearer`（`PROTOCOL.md §6`） |
| Q2 | 是否回显 `reqId` | ✅ **已关闭** | 请求带 `reqId` 时响应回显 `reqId` + `kind='response'`；SDK 默认并发 |
| Q3 | 广播/推送信封规范 | ✅ **已关闭** | `kind='notification'` + 可选 `cmd/subCmd`/`type`，唯一构造入口 `createNotificationMessage` |
| Q4 | 应用层心跳 Action | ✅ **已关闭** | `system.ping = (1,1)`，免鉴权 |
| Q8 | HTTP API 与 WS 票据是否同源 | ✅ **已关闭** | 同一 JWT：REST 登录签发，WS 握手校验 `payload.id` |
| Q7 | 生产是否启用 ionet-ts WS | ⚠️ **部分关闭** | `allowProduction` 开关已就位；部署形态（attach/独立端口/Java External）仍需运维决定 |
| Q5 | 业务错误码表 | ❌ **仍开放** | 当前仅 `ActionError` 四码（`UNAUTHORIZED`/`INVALID_PARAM`/`CHARACTER_NOT_FOUND`/`FORBIDDEN`）；完整码表待后端补 → 前端建映射表 |
| Q6 | 响应是否携带 `serverTime` | ❌ **仍开放** | 离线收益时间同步仍需后端提供字段或首 Action 约定 |
| Q9 | 是否启用 HTTP fallback 通道 | ❌ **新增** | 当前 `httpServer: false`；若要降级需后端开启并配独立前缀（`PROTOCOL.md §9.1`），注意 HTTP 不产生 `reqId`/`kind` |
