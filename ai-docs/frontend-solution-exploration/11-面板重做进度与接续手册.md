## 2. 重做一个面板的标准步骤（照做即可）

参考实现：`packages/web/src/pages/game/panels/ZonePanel.tsx`（+ 同目录 `zone/ZoneCard.tsx`、`zone/presentation.ts`）。

1. **读玩法规格**：`10-玩法驱动的面板设计.md` 中该域的 §1.x（玩家目标 / 关键数值 / 动作清单 / 建议界面结构 / 必须隐藏的字段）。
2. **查 store API**：见本文 §3 速查表；字段可直接 `seed`，方法即交互。
3. **写容器面板** `panels/<Name>Panel.tsx`：
   - `observer(...)` + `useRootStore()`；**不在挂载时拉取**（首屏由 `RootStore.loadPanel()` 并发加载）；
   - 三态交给 `AsyncBoundary`；破坏性/不可逆操作用 `ConfirmAction`；数值用 `formatCompactNumber` / `formatDuration`；
   - 结构按「问题驱动三段式」（zone 的样板）：**现在什么情况 → 能做什么 → 做完得到什么**；
   - **协议字段不上屏**：`code` 只做 key/testid、`orderIndex` 只排序、`unitCode/bossCode/…` 不展示；
   - 单文件 ≤250 行（门禁）；超了就像 zone 一样把子组件/纯函数拆到同目录子文件夹。
4. **写测试** `panels/<Name>Panel.test.tsx`（≥5 例，参考 `ZonePanel.test.tsx`）：
   - 用 `test/helpers/panel-harness.tsx` 的 `createPanelHarness()`（假适配器 + 假 fetch + `requests` 记录 + `seed` + `connect`）；
   - 覆盖：正常渲染 / 空态 / loading+error / **交互真的发出对应 `cmd/subCmd`**（常量从 `@idle-path/ionet-transport` 导入，**不要写字面量**）/ 边界（`null`、空数组、极值）；
   - 交互用例**必须先 `await harness.connect()`**。
5. **翻牌**：`pages/game/panel-registry.tsx` 把该域 `status` 改 `'ready'` 并挂 `panel: <XxxPanel />`（**只改这一处**，导航与页面壳不动）。
6. **删旧版**：删除同名的旧面板文件（若第 1 步是覆盖写入，则其旧测试需重写）。
7. **验证**：
   ```bash
   pnpm --filter idle-path-web exec vitest run src/pages/game/panels/<Name>Panel.test.tsx src/pages/game/GameShellPage.test.tsx
   pnpm --filter idle-path-web run typecheck
   # 收口时（每个批次）
   pnpm --filter idle-path-web run test        # 含 hygiene 门禁
   pnpm --filter idle-path-web run build
   ```

> 若某域需要新 ui-kit 组件：先按 `packages/ui-kit/README.md` 的「新增一个组件的步骤」建组件 + 同目录测试，
> 再在 `packages/ui-kit/src/index.ts` 对应分组加 `export *`（**barrel 由主线统一改**，避免多人冲突）。

## 4. 已锁定的约定（不要回退）

1. **协议只有一份真相**：`PROTOCOL.md` + `@nbb-ionet/client-protocol`；前端不自造信封/codec/关联。
2. 面板是**容器**：只做「store → ui-kit props」映射，不写业务规则/公式；三态走 `AsyncBoundary`。
3. **协议字段不上屏**；数值/时长必须经 `formatCompactNumber`/`formatDuration`（禁裸浮点）。
4. **组件能抽就抽（硬要求，用户明确定调）**：坚决不允许单文件聚合无数组件去实现一个页面。
   落地判据：
   - 一个文件只放一个组件（只导出一个组件），子组件拆到同域子目录（`panels/<域>/Xxx.tsx`）；
   - 纯逻辑/映射/计算拆成同目录 `presentation.ts`（+ 同目录单测），组件里不内联长映射表与公式；
   - 页面文件**只做编排**：现状即 `panels/*Panel.tsx` 109~196 行、每个域都有 `panels/<域>/` 子件目录；
   - 后续玩法调整新增的界面同样适用——**不要**因为「先跑通」就把子件堆回面板文件。
5. ui-kit：只用 antd、受控、props ≤10、一组件一目录一文件 + 同目录测试、禁 hex/`!important`/`<style>`、不传 `size`。
6. 反馈 API 一律 `App.useApp()`；禁 antd 静态 `Modal.confirm` / `message.*`。
7. 新增游戏域 = 只改 `panel-registry.tsx`。
8. 改 antd 代码前先查官方 CLI（`AGENTS.local.md` §6，含已踩过的弃用对照表）。

## 6. 接续时的已知坑

- **测试必须先 `await harness.connect()`** 才发得出 WS 请求（否则停在「等待连接就绪」）。
- 断言 antd 文案时注意：**两个汉字的按钮会被插空格**（可访问名是「登 录」），用 `/登\s*录/`；
  带图标的菜单项可访问名含图标 `aria-label`（如「compass 秘境」），同样用正则。
- `AppShell` 移动端抽屉用**捕获阶段**关闭（antd `Menu` 条目会 `stopPropagation`）。
- antd v6 已弃用项见 `AGENTS.local.md` §6 表（`Drawer width→size`、`Card bordered→variant` 等）。
- 测试慢：单文件 33~45s；两包紧挨着跑偶发超时，已把 `testTimeout` 放 60s、worker 数限「一半核数」。
- **vitest worker 坑（已修，别再踩）**：`maxWorkers` 在 vitest 1.6 只接受**数字**，
  写成 `'50%'` 会让 `Number('50%')`→NaN 进 tinypool → `RangeError: Invalid array length`；
  只设 `maxWorkers` 还不够——`minWorkers` 缺省是 `numCpus - 1`，会撞
  `options.minThreads and options.maxThreads must not conflict`。
  **必须两个一起设**（见 `3e3b27c`）。多个子代理并行时应再加 `--maxWorkers=2 --minWorkers=1` 让出 CPU。
- 沙箱环境坑：pnpm store 只读（`AGENTS.local.md` §5）、antd CLI 缓存需指到 `tmp/`（§6）。
