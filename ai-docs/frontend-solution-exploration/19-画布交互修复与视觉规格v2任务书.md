## 2. T1 · 拖动抑制（**先做这个，两个 bug 一起消失**）

`packages/ui-kit/src/layout/GraphCanvas/index.tsx`：

1. 容器 `style` 补（TS 里 `WebkitUserDrag` 需要 cast 或写进 `as CSSProperties`）：
   ```ts
   userSelect: 'none',
   WebkitUserSelect: 'none',
   WebkitUserDrag: 'none',
   ```
2. `onPointerDown`（在 `use-graph-viewport.ts`）**第一行加 `event.preventDefault()`**
   —— 阻止原生选择起步。容器没有 `tabIndex`、不需要聚焦，所以不会影响键盘可达性。

## 10. 为什么**不**换 canvas（供决策留档）

用户问「如果采用 canvas，会更麻烦吗」。**答案是：更麻烦，而且治不了这三个 bug。**

1. **架构本来就已经是「SVG + div」**：连线/网格是 SVG，枢纽是**绝对定位的 div**。
   换成 `<canvas>` 只会把连线那一层换掉。
2. **枢纽必须是 antd 组件** —— 这是用户最初的要求（「直接使用 antd 组件去渲染」）。
   `<canvas>` 里**塞不了 antd 组件**，只能自己画；那就等于放弃 antd 的主题、紧凑、无障碍。
3. **全 canvas 的额外成本**：字形度量与换行、HiDPI 缩放、命中测试、**无障碍**（canvas 对读屏器完全不透明，
   得再维护一份 DOM 列表）、主题 token 要手动取再喂给绘制调用、测试要从「断言 DOM」改成「mock canvas context」。
4. **这三个 bug 在 canvas 里照样存在**：canvas 上拖动**同样会选中周围文字**（浏览器按整个文档选区算）、
   **同样要 `preventDefault`**；平移数学也照样要写。
5. **canvas 真正的适用场景是几百上千个节点**的性能。我们现在 **17 个枢纽**，离那个门槛差两个数量级。

**结论**：该补的是**拖动抑制**，不是换渲染技术。

### 11.2 B1「点前往 → 白屏」的真因（**重要：不是 render 期异常**）

§0 对 B1 的「render 期未捕获异常」**未被证实** —— 它当时的唯一证据是「全仓没有 ErrorBoundary」，
那是「如果有异常会白屏」的机制，不是异常本身。SESSION-B 用**真后端（:3000）真实 payload** 回放，
排除了以下五条路径，均**未复现崩溃**：

1. 真 payload 逐节点渲染 sweep（17 枢纽 × 四环层 × current/visited/known × disabled）；
2. `MapPanel` 全部 17 节点「点枢纽 + 点前往」；
3. 整壳 `GameShellPage` + `React.StrictMode` + 真 payload（切地图 → 点枢纽 → 点前往）；
4. **忠实回放**：真后端注册建角 → 进东门 → 进第六峰（=用户截图状态），对全部可进入节点
   （四门 / 第五峰 / 第七峰 / 育灵园）逐个真跑 `map.enter` 取真实回包，再逐个回放点「前往」；
5. 窄屏 Drawer 路径 + 真实 `getBoundingClientRect`（900×520，让 `zoom_fit` 真的执行）。

**已定位并修复的真因（可复现）**：`MapStore.enter` 同步置面板级 `loading = true`，
而 `AsyncBoundary` 的 `loading` 优先级最高 → 点一下「前往」**整块面板（画布 + 详情）被卸载**，
换成 3 行骨架屏；WS 慢或正在重连时这个白会一直持续到 transport 的 10s 请求超时。
这就是「点前往 → 界面直接白屏」的形态。

修法（用户指定口径）：`loading` 只服务于「首屏 / 整图重载」，不服务于「移动」。
新增 `MapStore.refreshQuiet()`（不碰 `loading`/`error`，失败保留旧数据只 toast，且用**独立**
`LoadGuard` —— 与 `load()` 共用序号会让在飞的 `load` 收尾被丢弃、`loading` 永久卡 true），
`enter`/`waypoint` 改走它；移动反馈改成**按钮级** `moving`/`movingTo`。

**另一个同源症状**（B2「飘到左边」/ B3「选中一串带空格数字」）：拖动原生选区会自动滚动
最近的可滚动祖先，界面被滚出可视区看起来也是白 —— 已由 T1 从源头消除（不做任何 Edge 特判）。

**ErrorBoundary 保留**：它是诊断手段。若以后再白屏，那张错误卡（标题 + message + 组件栈）
就是真因；若只是画布变白而侧栏还在，说明是上面这条 loading 口径问题。
