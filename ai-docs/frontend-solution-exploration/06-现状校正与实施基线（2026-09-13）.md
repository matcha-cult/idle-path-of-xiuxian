## 2. 重大遗漏：业务错误**不在** `errorCode` 上

原 `01 §3.3` / `§10.7` 写"客户端应统一判定 `errorCode !== 0` 为失败"。**这条不完整，会导致前端把全部业务失败当成功。**

| 层 | 失败表现 | 来源 |
|---|---|---|
| 传输/框架层 | `errorCode: 404`（路由未注册）、`500`（Action 抛错）、`400`（坏帧） | `PROTOCOL.md §8` |
| **业务层** | **`errorCode` 为 `0`/缺失，但 `data.success === false`，且 `data.data.code` 为业务码** | `packages/server/src/ionet/action-support.ts:1-17` |

本项目 Action 的硬约定：**不抛异常**，统一返回 `{ success, message, data? }`，被 `BarSkeleton.execute` 包进响应信封的 `data` 字段。已知业务码（`ActionError`）：`UNAUTHORIZED` / `INVALID_PARAM` / `CHARACTER_NOT_FOUND` / `FORBIDDEN`。

**前端判定顺序（必须写进 SDK 与 ToastStore）：**

```ts
// 1) 传输层失败
if (res.errorCode !== 0 && res.errorCode !== undefined) → TransportError(errorCode)
// 2) 业务层失败（本项目主路径）
const body = res.data as { success?: boolean; message?: string; data?: { code?: string } };
if (body?.success === false) → BusinessError(body.data?.code ?? 'UNKNOWN', body.message)
// 3) 成功
```

> A3 提供 `isSuccess(envelope)` 仅覆盖**传输层**判定，**业务层判定需前端自建**。

## 3. A3（`@nbb-ionet/client-protocol`）能力边界 —— 决定 SDK 缩小范围

| 已由 A3 提供（**不要重造**） | 前端 1.5 仍需自建 |
|---|---|
| 信封类型：`RequestMessage` / `ResponseMessage` / `NotificationMessage` / `WireFrame` / `ResponseKind` | **transport**：`BrowserSocketAdapter`（原生 `WebSocket`；后期 wx/qq） |
| `createRequestMessage` / `createResponseMessage` / `createNotificationMessage` / `isSuccess` | **client 状态机**：连接/重连/退避/心跳/生命周期感知 |
| `envelopeCodec`（JSON、**未知字段透传**，向前兼容） | **认证钩子**：`?token=` 注入 + 重连重签 |
| `classifyFrame` / `isNotificationFrame`（按 `kind` 分流） | **API/DTO 层**：typed services + 业务错误转译 |
| `RequestResponseAssociator`（reqId 精确 + FIFO 回退） | **应用层**：Store 树、ToastStore、时间同步 |
| `./testing` 子路径：`ENVELOPE_GOLDENS`（与 A1 主套件共享的金样） | 业务 DTO（由 codegen 同步，见 §4） |

> **原则**：协议只有一份真相（`PROTOCOL.md` + A3）。SDK 若再自造一套信封/codec，就是第二份真相，违背 A1/A3 "金样同源"的初衷。

### 3.1 消费路径（已验证可行）

根 `pnpm-workspace.yaml` 已含 `vendor/ionet-ts/packages/*`，前端包可直接声明：

```json
{ "dependencies": { "@nbb-ionet/client-protocol": "workspace:*" } }
```

版本随 submodule 钉住，与后端同源。**不存在"包拿不到"的阻塞。**

### 3.2 命名建议

原 `02 §4.3` / `04 D3` 规划的 `packages/ionet-client` 与 A3 概念撞车（A3 才是"协议 client"）。
建议更名为 **`packages/ionet-transport`**（transport + 状态机），或直接并入 `packages/web`。

## 7. 一句话给 1.5 的实施铁律

1. 协议只认 `PROTOCOL.md` + `@nbb-ionet/client-protocol`，**不重造协议层**；
2. 业务失败判定必须同时看 `errorCode` **和** `data.success === false`；
3. 默认 **reqId 并发**，串行仅作兜底；
4. 浏览器鉴权走 **`?token=`**；心跳走 **`system.ping (1,1)`**；
5. 禁 import Node-only 的 `@nbb-ionet/*`，**但 A3 是白名单例外**。
