## 1. 挂机后端现状（**已实现、已实测**）

> ⚠️ 其中 §1.3 的「打哪一层」这一段**本轮要按 A3 改掉**（见 §3.5）；

### 1.1 协议面

| 动作 | 说明 |
| --- | --- |
| `zone.idleTarget` **(100,9)** | `{ zoneCode }` → 设挂机点。**准入：已突破（`clears ≥ 1`）∧ `idle_allowed`**；否则 `ZONE_NOT_IDLE_ELIGIBLE` |
| `zone.zones` **(100,1)** | `data.idleTarget` = 当前挂机点 code（null = 未设置）；`data.zones` = 已突破秘境；`data.breakthrough` = 全 13 境 |
| `idle.status` **(130,1)** | 离线时长 / 预计击杀 / 预计灵韵 / 今日物品上限 / 配置（60 轮·时、60%、12h 上限） |
| `idle.settle` **(130,2)** | 结算离线收益。**闸门顺序（真后端 e2e 抓出并修正）**：① 参数校验 → ② `ONLINE_BATTLE_ACTIVE` → ③「暂无可结算收益」早退 → ④ `IDLE_TARGET_NOT_SET` → ⑤ 结算 |

### 1.2 数据

```sql
game_idle_state(id, character_id UNIQUE, zone_id, updated_at)   -- 一人一个挂机点
game_idle_counters(character_id, day, items_produced)           -- 每日物品上限 200
characters.last_settle_at                                        -- 计时锚点
```

### 1.3 结算口径（`idle.service.ts`）

```
有效小时 = min(离线小时, 12) × 60%
击杀数   = floor(离线小时 × 60 轮/时 × 60%)
单位     = idleEncounter(characterId) → 挂机点秘境，floor = min(progress.floor, maxFloor)
           ⚠️ 已突破秘境的 progress.floor = maxFloor = 第 3 层 = **Boss 层** ⇒ 挂机**打在 Boss 上**
           ➡️ **本轮按 A3 改为「循环整轮、按层分摊」，规格见 §3.5**
产出     = combatLogic.settleKills(kills, { itemBudget: 200 - 今日已产 })  -- 既有辨宝法阵
```

### 1.4 硬不变式（**绝不能破坏**）

1. **离线时间只能兑换产出，不能兑换进度**：挂机**不涨层、不给 `clears`、不写 `game_zone_progress`**（现实现已如此）；
2. 客户端**不本地算产出**（R2 §4.2）；
3. 在线战斗期间（`game_zone_state` 有行）挂机**被拒**（`ONLINE_BATTLE_ACTIVE`）；
4. 特殊秘境（6~13 境）**不可挂机**（`idle_allowed = false`）；
5. 未突破的秘境**不可设为挂机点**。

### 3.5 A3 实现规格：挂机打「整轮」而不是「最深层」

**现状（要改掉）**：`ZoneService.idleEncounter` 取 `floor = min(progress.floor, maxFloor)`，
已突破秘境 ⇒ `floor = 3 = Boss 层` ⇒ 挂机一直在打 Boss（`unit_code = boss_code`）。

**目标**：一轮 = 该秘境的全部 `maxFloor` 层（13 个秘境都是 3 层），击杀**按层均分**，
每层用自己的单位 / 门槛 / 层灵韵 / 掉落档 / Boss 额外判定，最后聚合结果。

**接口改造建议**（`zone.service.ts`）：

```ts
/** 一次挂机「整轮」的逐层计划（替换/包装现有 idleEncounter） */
export interface ZoneIdleFloor {
  floor: number;
  unitCode: string;          // Boss 层取 boss_code
  isBoss: boolean;
  floorRequirement: number;  // floorRequirement(zone, floor)
  lingyunBonusFlat: number;  // floor × lingyun_bonus_per_floor
  tierOffsetBonus: number;
  dropDrawBonus: number;
}
export interface ZoneIdlePlan {
  zoneCode: string;
  zoneName: string;
  floors: ZoneIdleFloor[];   // 升序 1..maxFloor
}
// zone.service: idlePlan(characterId): Promise<ZoneIdlePlan | null>
//   null 的两种原因不变：没设挂机点 / 挂机点不再满足 idleEligible
```

**`idle.service.settle` 的结算改造**：

1. `plan = zoneLogic.idlePlan(character.id)`；`null → IDLE_TARGET_NOT_SET`（不变）；
2. **击杀分摊**：`n = plan.floors.length`；`per = Math.floor(plan.kills / n)`；余数
   `rest = plan.kills - per * n` **给第 1 层**（或平均摊到前 `rest` 层；二选一，单测钉住即可）；
3. **逐层 `settleKills`**：层 i 用 `per(+1)` 击杀与**该层自己的** `lingyunBonusFlat /
   tierOffsetBonus / dropDrawBonus`；`itemBudget` 逐层递减（`max(0, cap - produced - 已用)`），
   层间**不得**把预算用超；
4. **聚合**（`settleKills` 返回的是单次聚合，需自己加总）：
   - `lingyunGained` / `lingyunBonus` / `itemsProduced` / `kept` / `salvaged.count`+`lingyun` /
     `sold.count`+`spiritStones` / `blockedByTier` / `discarded`：**数值累加**（`salvaged/sold` 是对象，须逐字段加）；
   - `items`：**数组合并**（注意整体 50 件上限，若超要截断并计入 `discarded` 或单独字段——单测钉住口径）；
   - `currencies` / `essences`：**按 key 累加**；
   - `lingyunTotal`：取**最后一次**（或首层 total + 累加 gained，二者应一致；选一个并单测）；
   - `unit`：多层不再有单一单位 → 响应里 `unit` 改为 `undefined/null`，或给 `units: string[]`；
     **前端 `IdlePanel` 的结算展示依赖 `unit.name`，需要同步改**（见 §2 的组件清单）；
5. **绝不写 `game_zone_progress`**（不变式 1）：挂机不给层数、不给 `clears`；
6. **响应体**：`zone` 从 `{code,name,floor,isBoss}` 改为 `{code,name,floors}`（或保留 floor 字段并加 `floors`），
   前端展示「本轮 3 层」而不是「第 3 层」。

**必须覆盖的边界单测**：
- `kills = 0`（早退分支不变）、`kills = 1`（不足 3 层 → 只打第 1 层）、
- `kills` 与 `maxFloor` **不整除**（余数分配正确）、`maxFloor = 1`（单层秘境，退化为现状）、
- 每日预算**中途耗尽**（后几层 `itemBudget = 0`，仍应给灵韵/通货/精华）、
- **Boss 层的额外掉落判定确实生效**（该层 `dropDrawBonus` 含 `zoneBossExtraDraws`）、
- 3 层都被调用且参数正确（`settleKills` 调用 3 次、单位分别是 unit/Boss）。

### 3.6 B2 实现规格：上线/进挂机面板自动结算一次

- **时机**：登录成功建角之后、或**首次**打开挂机面板时，自动调一次 `idle.settle()`；
- **防重复**：`settle` 成功会刷新 `characters.last_settle_at`，因此重复调用天然退化为
  「暂无可结算收益」（成功信封）——**不需要**额外幂等键；但**不要**在每次面板刷新都调
  （否则每次刷新都弹一次空 toast）；
- **建议实现**：在 `IdleStore` 上加一次性标志（如 `autoSettled: boolean`）或由 `RootStore`
  在 `loadPanel()` 后触发一次；用户手动「再结算」按钮保留；
- **前端展示**：沿用现有 `idle-settlement`（`SettlementSummary`），但要适配 A3 的多层结构（§3.5 第 6 条）；
- **边界**：战斗中（`ONLINE_BATTLE_ACTIVE`）自动结算**不应弹错误 toast** —— 应静默跳过
  （面板显示「已暂停：在线战斗中」）。这一条要用单测钉住，否则每次上线都弹一条红色提示。
