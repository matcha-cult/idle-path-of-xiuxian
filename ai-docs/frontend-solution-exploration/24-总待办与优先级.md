### G1 · 特殊秘境 6~13 境突破道具（§22 Q7 唯一未实装玩法）

**现状（玩家视角的死胡同）**：13 个秘境里，1~5 境（历练）免费可玩，**6~13 境（特殊）点不动** ——
石台那一行是 Tooltip「需特殊道具，后期实装」+ 按钮 `disabled`。

**证据链**

| 层 | 事实 |
| --- | --- |
| 种子 | `prisma/seeds/game/zones.json` 的 6~13 境有 `unlockItemCode: item_mijingling_r6..r13`，但**没有名为这些 code 的道具** |
| 类目 | `prisma/seeds/game/item-bases.json` 只有 8 个**装备**类目（weapon/helmet/body/gloves/boots/belt/ring/amulet）——**没有「道具 / 消耗品」类目** |
| 服务端 | `zone.types.accessOf()`：special ⇒ `{ canBreakthrough:false, reason:'item_required', itemCode }`；`zone.service.breakthrough()` 直接回 `ZONE_ITEM_REQUIRED`（**不校验、不消耗**任何道具） |
| 客户端 | `RealmBreakthroughRow.tsx:38` Tooltip「需特殊道具，后期实装」；`ionet-transport/dto.ts:624` 注释「道具未实装」 |
| UI 文案 | `RealmBreakthroughRow` 只显示"要不要道具"，**不显示"你有没有"**（因为协议里没有持有数） |

**要做的事（建议顺序）**

1. **设计**：道具从哪来、怎么消耗（见 §3 D1）→ 出小任务书；
2. 物品域：新增「道具 / 消耗品」类目（或复用 `game_essence_inventory` 思路，二选一，见 §3 D1）；
3. 种子：8 个道具（`item_mijingling_r6..r13`）+ 掉落来源 + 自检（`init-game-db.mjs` 已有"special 必须有 unlockItemCode"的校验，可对称加"code 必须能在 item-bases 里解析到"）；
4. 协议：`ZoneBreakthroughView` 加「持有数 / 是否足够」（**或**复用既有 item 域查询，避免协议膨胀）；
5. 服务端：`breakthrough` 消耗道具（**事务内**：校验 → 扣 → 进战斗），失败码沿用 `ZONE_ITEM_REQUIRED`，补 `ZONE_ITEM_NOT_ENOUGH` 之类；
6. 客户端：石台行显示「所需 N / 拥有 M」+ 不足时指路来源；道具持有数变化要刷新；
7. **边界单测（同 commit，`AGENTS.local.md` §4）**：数量恰好够 / 差 1 / 为 0 / 道具 code 在种子里悬空 / 重复点击并发 / special 与 training 分支不互相污染。

**风险**：这是**唯一会动玩家资产**（扣道具）的改动 ⇒ 必须走事务 + 幂等思考（连点两次不能扣两次）。

### E3 · `map.service` 的 `discovered` 过滤器隐患

`map.service.ts:233-239`：

```
const discovered = discoveredCodes(nodes, byNodeId);
...
const visible = mapNodeRows.filter((n) => discovered.has(n.code));
```

今天**恰好空转**（17 个节点的 `requires_node_code` 全是 `null`）。但 `requires_node_code` 正是为剧情前置保留的字段 ——

## 5. 环境与门禁（压缩后**必须重新确认**）

| 项 | 事实 |
| --- | --- |
| Postgres **35432** / Redis **6379** | 用户在宿主侧用 docker 启动（沙箱内无 docker socket，只有 psql 客户端） |
| 后端 `:3000` / vite `:5173` | **会话级后台任务**，压缩/重启即丢 → 用 `job_list` 确认；**改服务端源码必须 `tsc` + 重启**（否则跑旧 dist，本仓踩过多次） |
| DSH GUI `:3080` | **不要动** |
| DB 迁移顺序 | `db:migrate:realm` **先**，`db:init:game` **后**；两条路径不得漂移（`zone-schema.test.ts` 守着） |
| 真后端 e2e | `node dist/main.js` 起来后：`tsx scripts/e2e-all.mts` / `e2e-journey.mts`；web 用 `IONET_E2E=1 vitest run test/real-backend.e2e.test.ts`（~95 s） |
| 别用 `npx` | 沙箱里 npm 缓存只读 → 用 `./node_modules/.bin/...` |
| 改前端 UI 前 | 先查 antd CLI：`XDG_CACHE_HOME=$PWD/tmp/antd-cache antd --lang zh --version 6.6.3 info|doc|demo|token <C>` |
| 硬约束 | 一组件一目录一文件 + 同目录单测；`.tsx` 只导出一个组件；禁 `export default`；禁内联 hex；web `src/` 单文件 ≤199 行（`wc -l` 口径）；**不传 `size`**（紧凑恒开）；反馈走 `App.useApp()`；**业务代码改动必须同 commit 带边界单测** |
| 门禁命令 | 见 §0 的基线块；`packages/server`：`tsc -p tsconfig.json` / `tsc -p tsconfig.test.json` / `tsx --test "test/**/*.test.ts"` / `tsx scripts/check-deps.mts` |
