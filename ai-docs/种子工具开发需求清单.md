## T1 · 地图编辑器（**用户提出，待开发**）

### T1.1 一句话定位

> 一个开发期的 Web 界面，**只做一件事**：产出某张大地图的种子数据。
> 用户在界面上**拖动枢纽点**（底下铺着该图的背景图），导出即可直接落库。

### T1.2 必做能力

| # | 能力 | 说明 |
| --- | --- | --- |
| 1 | **坐标点阵** | 按 `(grid_cols, grid_rows)` 铺出**交叉点阵**（坐标 `0..cols` / `0..rows`），轴标可见 |
| 2 | **铺背景图** | `background_key` 指向的底图，按自然尺寸 `(cols+1)×CELL_PX × (rows+1)×CELL_PX` 铺在最底层 |
| 3 | **拖动枢纽** | 拖到某个交叉点即吸附；拖动结果写回 `grid_row` / `grid_col` |
| 4 | **编辑枢纽属性** | `code / name / ring / sector / kind / feature_key / level / threshold / has_waypoint / chapter / requires_node_code / zone_code / description / order_index` |
| 5 | **新增 / 删除枢纽** | 含 `code` 唯一性检查 |
| 6 | **连边** | 两点之间拉线；`bidirectional` 可切；删除边 |
| 7 | **拓扑校验（实时）** | `requires_node_code` 是否存在、全图连通性、`kind=secret_realm` ≤ 1（D8）、`kind` 取值合法性 |
| 8 | **几何校验（实时）** | 见 T1.3 —— 这些正是 `gen-map-seed` 的自检项，编辑器要**边拖边报** |
| 9 | **导入**既有种子 | 反向打开现有地图（如青云宗）继续编辑 |
| 10 | **导出** | `maps.json` / `map-nodes.json` / `map-edges.json`，**与现有种子同形**（可直接替换） |
| 11 | **缩放 / 平移** | 与前端画布**同一套坐标系与 `CELL_PX`**（§14） |

### T1.3 实时校验项（与 `gen-map-seed` 自检同源）

| 检查 | 级别 |
| --- | --- |
| 坐标越界（`<0` 或 `>cols/rows`） | 硬 |
| 撞格（两枢纽同坐标） | 硬 |
| `requires_node_code` 悬空 | 硬 |
| 孤立枢纽 / 不连通 | 硬 |
| 秘境数量 > 1 | 硬 |
| **连线交叉数** | 硬（阈值） |
| **不相邻枢纽最小间距** | 软（只提示） |
| **落点最大偏移**（相对理想环，可选） | 软（只提示） |

### T1.4 明确**不做**

- ❌ 编辑关卡内容（怪物、掉落表、秘境层数仍在各自种子文件里）；
- ❌ 多用户 / 权限 / 服务端持久化（**导出即结果**，不建后端）；
- ❌ 上线正式服（开发期工具）；
- ❌ 美术编辑（底图是外部出图，编辑器只负责铺上去对齐坐标）。

### T1.5 形态建议

- **复用前端同一套坐标与渲染原语**（ui-kit `GraphCanvas`）——
  **编辑器是 `GraphCanvas` 的第二个消费者**，这反过来验证它是不是真的「可通用」，
  而不是为地图一次性造的轮子（`11-面板重做进度与接续手册.md` §4 的要求）；
- 放 `packages/map-editor`（独立 workspace 包）或 `packages/web` 下的一条独立路由 —— **待定**；
- 拖动用 pointer 事件 + 吸附函数（纯函数，可单测）。

### T1.6 验收标准

> 给一张新图（如第 3 章的「山下凡尘」），**能在 30 分钟内从空白点阵做出
> 一个 `pnpm gen:map-seed` 自检全过的种子**，且不需要手改任何 JSON 数字。
