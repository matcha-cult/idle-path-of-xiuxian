# P2.5 境界突破 — 计划 / 契约 / 规格（合一文档）

> 依据：v2 设计 §2.2（突破规则）+ §2.1（十四境表）+ P2 澄清清单 ①★A（突破另排）
> 状态：执行中

---

## 1. 规则固化

| 规则 | 结论 |
| --- | --- |
| 触发 | 消耗灵韵突破，**必定成功**（设定修改 11 的收敛实现：无失败路径 = 永不触发惩罚；如需随机失败期预留 successRate 配置位） |
| 成本 | `realmBreakthroughCosts` 配置数组（递增公式预设 200×n²）：1→2=200，…，13→14=33800 |
| 边界 | realm 1~14；14=合道封顶，再突破 → MAX_REALM_REACHED |
| 联动 | realm+1 自动解锁更高 T 阶装备（P1 已实现 TIER_TOO_HIGH 守卫，无需改动） |
| 禁则 | 无战斗中突破（本游戏无战斗中概念，天然满足） |
| 存储 | 单库单表（characters.realm/lingyun），一条原子 UPDATE 完成扣费+升境 |

## 2. 配置扩展（config/app.config.json）

```jsonc
"realmBreakthroughCosts": [0, 200, 800, 1800, 3200, 5000, 7200, 9800, 12800, 16200, 20000, 24200, 28800, 33800],
// index = 当前境界 → 升下一境消耗；index 0 占位；14 封顶无下一境
```

## 3. 境界名称表（REALMS，常量）

铜皮/草根/柳筋/骨气/铸炉/洞府/观海/龙门/金丹/元婴/玉璞/仙人/飞升/合道（1~14）。

## 4. API

| 方法 | 路径 | 说明 | 失败码 |
| --- | --- | --- | --- |
| GET | /api/game/breakthrough | { realm, realmName, nextCost(null=封顶), isMax } | — |
| POST | /api/game/breakthrough | 突破（扣费+升境原子更新） | LINGYUN_NOT_ENOUGH / MAX_REALM_REACHED / CHARACTER_NOT_FOUND |

成功示例：`{ "success": true, "message": "突破成功：铜皮 → 草根", "data": { "realm": 2, "realmName": "草根", "lingyun": 0 } }`

## 5. 冒烟清单

1. 新号建角（realm=1 铜皮）→ GET 显示 nextCost=200
2. POST 无灵韵 → LINGYUN_NOT_ENOUGH
3. grant 200 → POST → realm=2 草根，剩余 0；再 POST → 需 800 → 不足
4. grant 1,000,000 → 连冲到 realm=14 → 剩余 = 1,000,000−Σcost
5. 14 境再 POST → MAX_REALM_REACHED；character/info realm=14
6. 装备联动：此前境界 1 被拒的 T2 物品，升境后 equip 成功
7. dev 限流与 401 回归；/api/health 200
