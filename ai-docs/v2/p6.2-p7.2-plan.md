# P6.2 / P7.2 实施计划 — 事件计数 + 演出编排

> 依据：v2 设计 §7.3（剧情配置种子化/演出）、§11.7-11.8（任务）；P6/P7 遗留项
> 状态：执行中

---

## 1. 范围收敛（批决策）

| 决策 | 结论 |
| --- | --- |
| **P6.2 事件计数** | 新增通用计数表 `game_stat_counters`；`StatService` 提供 increment/recordKill/readAll |
| 击钩子 | `UnitService.settleKills` 统一记录：`kill_total` / `kill:<unitCode>` / `kill_realm:<realm>`（kill/challenge/idle 全部覆盖） |
| 其他钩子 | `RealmService.breakthrough` → `breakthrough_total`；`CraftService.craft` 成功/摧毁 → `craft_total` |
| 新任务目标 | `kill_total` / `kill_unit`(key=unitCode) / `breakthrough_total` / `craft_total`，实时读计数表 |
| 种子补充 | q_ch1_3 增 `kill_total ≥ 5`；q_ch2_3 增 `kill_total ≥ 30` 与 `craft_total ≥ 1`；q_ch3_1 增 `breakthrough_total ≥ 6` |
| **P7.2 演出编排** | 新增 `game_story_seen`；`GET /story/chapter/:chapter`、`GET /story/quest/:code` 返回有序剧本节点（章节 intro/outro + 任务 start/done），`POST /story/seen` 标记已读 |
| 节点键 | `chapter:<code>:intro|outro`、`quest:<code>:start|done` |
| 不做 | 逐句打字机/过场动画（前端职责）；任务线非全量校验（P7 已登记） |

## 2. 数据模型（+2 表 → 共 28 表）

```
game_stat_counters  通用事件计数（character_id, key, value, updated_at，UNIQUE(character_id,key)）
game_story_seen     演出已读（character_id, node_key, seen_at，UNIQUE(character_id,node_key)）
```

## 3. 模块

```
modules/game/stat/    StatService + StatModule（@Global，供 Unit/Craft/Realm/Quest 注入）
modules/game/story/   StoryService/Controller/Module（依赖 QuestModule 复用任务状态）
```

## 4. API（契约详见 p6.2-p7.2-api-contract.md）

- GET  /api/game/story/chapter/:chapter — 章节剧本节点（含已读状态）
- GET  /api/game/story/quest/:code — 单任务剧本节点
- POST /api/game/story/seen {nodeKey} — 标记节点已读（幂等）
- （无新增计数 API；计数经任务目标与后续阶段消费）

## 5. 冒烟清单

1. 建表 2 张（28 表）；无新种子
2. 击杀 N 次 → `game_stat_counters` 的 kill_total/kill:<unit>/kill_realm:<r> 正确累加（经任务目标反映）
3. idle 结算（432 杀）→ kill_total 大幅增长且 kill:<unit> 同步
4. 新目标：q_ch1_3 的 kill_total 达标后任务完成（结合 zone_best_floor）
5. 突破/炼器 → breakthrough_total / craft_total 增长（经 q_ch3_1 / q_ch2_3 目标验证或直接查计数）
6. 章节剧本：`GET /story/chapter/1` 节点顺序 = intro → q_ch1_1 start/done → … → outro，text 与种子一致
7. `POST /story/seen` 后对应节点 seen=true；重复标记幂等；未知章节/任务 → CHAPTER_NOT_FOUND / QUEST_NOT_FOUND
8. health 200 + P6/P7 关键回归

## 6. 风险 / 技术债

- 计数表随 key 增长（每单位一条 + 每境界一条）；量级可控，未来可归档。
- 计数与结算非原子 → 计数可能少记（不重复计）：以「结算成功后再计」顺序，偏差偏向玩家友好。
- 演出仅文本+已读，无播放状态机。
