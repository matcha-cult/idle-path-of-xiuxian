## A. 范围与前置

### ① P2 是否包含「境界突破」？
- **推荐 A**：P2 只做功法册/9 槽/修习/参悟（结构层），突破拆到 P2.5 或随灵韵消耗一并做
- 备选 B：P2 顺带做突破（消耗灵韵、无失败惩罚、无次数限制——规则已定，只缺数值配方）
- 影响：realm 变更有装备 T 阶联动（已实现的 TIER_TOO_HIGH 会自动生效）

### ② P2 阶段灵韵从哪来？（战斗/单位在 P4 才落地）
- **推荐 A**：开发接口注入（沿用 generate 的门禁：仅 POST、限流、环境守卫）
- 备选 B：任务奖励占位（任务系统 P6，P2 不可用）
- 备选 C：挂机离线产灵韵（规则属 P4，仅留字段）

### ③ P2 功法效果是否参与任何数值计算？
- **推荐 A**：只落库 + 渲染展示（战斗系统 P4 才存在，光环/伤害公式届时接入）
- 影响：P2 的「道基协同」「神识预算」只做**状态合法性校验与展示**，不做属性贡献

## B. 功法清单（种子）

### ④ 心法/术法初始阵容规模
- **推荐 A（P2 最小可用）**：心法 8 部、术法 12 部（每道基 ≥1 心法 + ≥1 术法）
- 备选 B：先 4 心法 + 5 术法（正好一整套 9 槽）
- 待你给定：是否沿用编号草案（心法：青莲剑典/九转玄功/离火心经/冰魄寒光/…）

### ⑤ 道基标签集合（daoji）
- v2 草案：剑 / 雷 / 火 / 冰 / 体 / 阵 / 丹 / 符
- **需确认**：是否增删（如 毒/鬼/风/金），以及「无属性」功法如何处理（daoji=null 不与任何流派协同？）

### ⑥ 同流派协同加成数值
- 候选：与主心法道基一致的术法，效果提升 **+20%**（或伤害/效率提升 25%）——请给数值或授权占位后 P4 调平

### ⑦ 每部功法的效果结构
- 心法（光环类）：建议 `{stat_pct: X%}` 形式（如 主心法：全属性 +15%；辅心法：攻击 +10%…每级递增）
- 术法：建议 `{skill_damage: 基础值}` 占位 + 描述文案（P4 接入战斗）
- 待确认：效果是否随参悟等级线性递增（每级 +5%？）

## C. 参悟与神识

### ⑧ 参悟（功法升级）消耗公式
- 候选 1（线性）：`消耗 = 100 × 当前等级 × 等级`（1→2 耗 100，9→10 耗 8100…按你定系数）
- 候选 2（指数）：`消耗 = 100 × 2^(等级-1)`
- **推荐线性**（放置游戏友好）；上限等级建议 **20 级**——请拍板（或给公式/上限/系数）

### ⑨ 神识预算数值
- 辅心法 `spirit_cost`：建议 10 / 20 / 40 / 80 四档，总预算 **100**
- 待确认：总预算写入 `app.config.json`（神识预算=100、每档值由种子定义）？

### ⑩ 换装规则
- 已定：「槽位即激活、换下即失活、随时可换」。待确认：**换主心法是否消耗灵石/材料**（建议 P2 免费换，P3 通货体系再谈成本）

## D. 数据模型与 API

### ⑪ 功法载体表
- **推荐 A**：新建独立 `game_skills`（心法/术法定义）+ `game_learned_skills`（角色已修习）+ `game_skill_panels`（9 槽，slots 存 JSON 字符串沿用 P1 约定）
- 备选 B：功法并入 item_bases（category=skill_gem，P1 旧草案）——不推荐：功法无 T 阶/无稀有度，强行并入破坏 item 体系纯净性

### ⑫ P2 新增 API 草案
- `GET /api/game/skills`（功法图鉴：全部功法 + 修习状态）
- `POST /api/game/skill/learn`（修习：消耗玉简类物品 → 永久入册）
- `GET /api/game/skill/panel`（当前 9 槽状态）
- `PUT /api/game/skill/panel`（装槽/卸槽/指定主心法与 3 辅）
- `POST /api/game/skill/enlighten`（参悟：消耗灵韵升级）
- 若④生效另加 `POST /api/game/breakthrough`（突破）

### ⑬ 玉简与获取
- 未开光玉简（可转任意功法）P2 如何进包：**推荐**新增开发接口 `POST /api/game/skill/jade-grant`（走 generate 同款门禁），或复用物品 generate 扩展 category
